# 控制台计划（基于玉子控制台改）

## 一、现状

我们已经有 `/dsh-agent-core/panel`（独立页面，玉子风格改过一版）：
总览 / 心跳 / 日记 / 规则体检 / 记忆检索 / 调试台 / 日志，七个分页。

**不够的地方**（对照玉子控制台）：

| 玉子有 | 我们缺 |
|---|---|
| 服务卡片带实时启停 | 只有状态，不能启动/停止 |
| 聊天记录页（分页、筛选、只看我） | 只能看原始日志 |
| 调试台（表单化调接口，带返回） | 只有固定几个动作 |
| 二维码登录 | 无 |
| 插件 · 升级页 | 无 |
| 人格页（直接编辑人格文件） | 只能改参数 |

## 二、目标形态

```
         ┌──────────────────────────────────────┐
         │ 她控制台                            │
         ├──────────────────────────────────────┤
总览  │ 服务卡：DSH / NapCat / 心跳 / 日记 / 任务 │
聊天  │ 会话浏览：分页、按人筛、只看我、复制原文  │
人格  │ 三段编辑器：IDENTITY / 语气卡 / 管规     │
记忆  │ 检索 + 长期事实 + 日记时间线            │
调度  │ 心跳参数 + 日记窗口 + 任务表（可停可跑） │
调试  │ 任意 action 表单 → 返回 JSON            │
日志  │ 五路日志 + 过滤 + 下载                  │
        └──────────────────────────────────────┘
```

## 三、改造顺序（每步都能独立跑）

1. **抽数据层**：把 `panel.html` 里的 fetch 逻辑抽到 `console/api.mjs`，页面只负责渲染
2. **加聊天页**：读 `.dsh\sessions\` → 解析事件 → 分页（这里要复用 `session-guard` 的解压逻辑）
3. **加人格页**：三段文件编辑（写前自动备份，复用 `meme-learn` 的备份策略）
4. **加调度页**：任务表 + 启停（`jobs.json` 读写，已支持）
5. **加调试台**：本质上就是 `qq-api.mjs` 的 Web 表单
6. **加二维码页**：读 NapCat 的登录态图（它自己会生成）

## 四、不做的事

- **不做多用户**：这套是单人自托管，加账号体系只会把简单的事弄复杂
- **不做远程暴露**：所有接口只监听 `127.0.0.1`，要远程就自己套隧道
- **不把密钥放前端**：NapCat 令牌只在服务端用，页面永远看不见

## 五、和开源的关系

控制台属于"架构"，会进开源包；但**人格页编辑的是私有内容**，所以页面存在、内容为空——
别人打开看到空表单，自己填自己的。
